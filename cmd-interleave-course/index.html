cmd_interleave 是怎么跑起来的
01

你到底运行了什么

`cmd_interleave` 不是一个普通的画图脚本。它是在 MATLAB 里临时搭了一条小型实验流水线: 选任务, 设预算, 轮流跑两种算法, 把船板设计送去 ANSYS, 最后把结果打包成一个 `.mat` 文件。

先用一句话抓住主线

1
脚本先定实验规则

任务组合是哪些, 每个算法最多做多少次 FE, 每个任务的种群大小是多少。

2
问题对象把任务整理好

`Ship_Panel_MTSO` 会把 `task3`、`task5` 这类任务转换成真正能被算法调用的函数、上下界和维度。

3
CEDA-DW 和 GA 轮流上场

同一组任务、同一份随机种子、同一份预算。脚本的重点不是并行跑，而是“交错跑完再对比”。

4
每个候选解都会落到真实结构评估

算法给的是归一化变量, 评估时会映射成真实尺寸, 然后送进 ANSYS 算质量和约束。

i
最重要的理解

你运行的不是“一个算法”, 而是一整条实验剧本。`cmd_interleave` 像导演, 负责安排谁上场、什么时候停、最后把什么东西写进结果文件。

这个剧本最关键的文件有哪些

MTO
cmd_interleave.m入口脚本: 设配置, 跑算法, 保存 interleave 结果
mto.m平台总入口: GUI 或命令行实验
Algorithms
Algorithm.m算法基类: 记最优值、记 FE、统一结果格式
GA.m单任务遗传算法
CEDA_MP_DUALCHANNEL_WEIGHTED.m当前脚本里更复杂的多任务算法
Problems
Ship_Panel_MTSO.m把船板任务包装成优化问题
APDL
Ship_Panel_Problem.m任务定义、变量上下界、APDL 宏生成
run_ansys_eval.m真正调用 ANSYS, 解析质量和应力结果

入口脚本最先做的配置

CODE 
active_tasks = [3 5];  % 修改为你想跑的任务组合
Reps = 1;              % 总重复次数
maxFE = 1800;          % 每个算法的总FE预算
N = 20;                % 种群大小
Results_Num = 50;      % 收敛曲线记录点数
Global_Seed = 2604;
Disable_Swap = true;   % 若算法含Swap参数，则强制关闭变量交换
PLAIN ENGLISH

这次实验只关注任务 3 和任务 5, 不是把整套 ship problem 全部跑一遍。

`Reps = 1` 表示这份脚本这次只做一轮重复实验。

每个算法最多花 1800 次 FE, 你可以把它理解成算法的总体预算。

每个任务子种群的目标大小是 20, 所以每一代不会无限膨胀。

收敛曲线最终只留 50 个采样点, 这是为了看图和存盘更轻。

全局随机种子固定成 2604, 这样重跑时更容易复现。

如果算法有 `Swap` 这个开关, 这里统一先关掉变量交换。

02

谁在参与这场实验

理解 `cmd_interleave` 的捷径, 不是背完整个仓库, 而是先认清“演员表”。你只要知道谁负责调度、谁负责出题、谁负责求解、谁负责工程仿真, 后面很多代码就会突然变好懂。

先认识 5 个核心角色

C

cmd_interleave

导演。它安排任务、算法、预算、随机种子和结果保存。

P

Ship_Panel_MTSO

翻译官。它把“任务编号”翻成上下界、维度和真正可调用的评估函数。

B

Algorithm 基类

公共骨架。记 FE、记每代结果、统一 `getResult()` 输出格式。

G

GA / CEDA-DW

真正提出候选设计的人。一个简单直接, 一个会利用跨任务迁移。

A

APDL + ANSYS

裁判。它不关心算法名气, 只认结构质量和应力约束。

问题对象是怎么把任务准备好的

CODE 
ship_prob = Ship_Panel_Problem();
active_tasks = Prob.ActiveTasks(:)';

for k = 1:numel(active_tasks)
    task_id = active_tasks(k);
    [lb{k}, ~, ub{k}] = ship_prob.get_design_space(task_id);
    fnc{k} = Prob.makeTaskFcn(task_id);
end
PLAIN ENGLISH

先拿到最底层的 ship panel 任务表, 它知道每个任务的真实工程参数。

把当前想跑的任务列表取出来, 这里通常就是脚本设进去的 `[3 5]` 这种数组。

逐个任务处理, 不偷懒也不假设所有任务都一样。

给这个任务取出上下界。也就是告诉算法: 哪些尺寸能动, 最小多小, 最大多大。

再给这个任务造一个专属评估函数。之后算法只需要调这个函数, 不用理解 ANSYS 细节。

i
一个很有用的软件工程模式

这里做的是 封装。算法只看见“任务函数”, 不直接碰 APDL 宏、结果文件和 ANSYS 路径。

把这些角色想成一个工作群

cmd_interleave

P

T

A
Algorithms

很好。我只管在 0 到 1 的归一化空间里提候选解, 然后把它们交给问题对象评估。

N
ANSYS

把真实尺寸给我。我会回传质量、弯曲应力、剪切应力, 以及约束是否超标。

03

一次 rep 是怎么推进的

`rep` 可以理解成“同一实验再独立重来一次”。它的存在不是为了热闹, 而是为了防止你被一次好运气或坏运气骗到。

一轮 rep 的骨架非常朴素

1
先固定随机种子

这样这次 rep 的随机数来源就被钉住了, 两个算法可以共享同一把“骰子”。

2
重新设置问题对象

脚本会再次调用 `prob.setTasks()`。这能保证任务边界和函数句柄是干净的一套。

3
给算法塞配置

`Result_Num` 决定收敛历史最终保留多少点, `Save_Dec` 决定是否把决策变量也存下来。

4
算法开始代际循环

GA 和 CEDA-DW 都会一代一代提出候选解, 评估后再筛一轮, 直到 FE 用完或早停触发。

脚本在每次开跑前做了什么

CODE 
rng(seeds(rep));
prob.setTasks();
algo = algos{a};
algo.Result_Num = Results_Num;
algo.Save_Dec = false;
if Disable_Swap && isprop(algo, 'Swap')
    algo.Swap = 1;
end
algo.reset();
PLAIN ENGLISH

先把这次 rep 的随机源锁到固定种子上。

把问题对象重新整理一遍, 避免上一个算法留下的状态影响这一个。

取出当前要跑的算法对象。

告诉算法: 收敛结果最后只留 `Results_Num` 个采样点。

这里明确不保存每代 `Dec`, 所以默认只保留目标值轨迹和最终最优解。

如果算法带 `Swap` 属性, 这里统一把它关成脚本想要的模式。

最后重置算法内部状态, 让它像刚开机一样开始这一轮。

Global_Seed = 2604 全局起点种子, 用来生成每个 rep 的实际种子
rep_seeds = (0:Reps-1) + Global_Seed 每次重复实验真正喂给 `rng()` 的数字
Result_Num = 50 收敛历史不会原样保存全部代数, 最后会重采样成 50 个点

算法基类每一代都会顺手记账

CODE 
flag = Algo.FE < Prob.maxFE;

gen = Algo.Gen;
isSingleObj = max(Prob.M) == 1;
for t = 1:Prob.T
    if isSingleObj
        bestSol = Algo.Best{t};
        Algo.Result(t, gen).Obj = bestSol.Obj;
PLAIN ENGLISH

先判断 FE 预算是否还没花完。没花完才能继续下一代。

取出当前代编号 `gen`。

这条 ship panel 链路是单目标问题, 所以这里会走 `isSingleObj` 分支。

按任务一个个记录当前代结果。

单目标时不保存整个人口, 只记住“这一代当前最优个体”。

第一件被记下来的就是最优目标值 `Obj`。

i
为什么这点很关键

很多人以为 `.mat` 里一定保存了每代每个个体。对这条单目标链路不是这样。默认保存的是“每代最好那一个”的历史, 不是完整人群快照。

04

变量如何变成钢板结果

算法嘴里说的是 0 到 1 之间的归一化数字, 工程软件嘴里说的是腹板高度、板厚和应力。中间这层翻译, 就是这条链路最“像工程”的地方。

第一步: 把归一化变量映射成真实尺寸

CODE 
Range = Prob.Ub{t} - Prob.Lb{t};
Lower = Prob.Lb{t};
x = Decs(:, 1:D) .* Range + Lower;

[Objs, Cons] = Prob.evaluate(x, t);
Algo.FE = Algo.FE + size(x, 1);
PLAIN ENGLISH

先算这个任务每个变量允许活动的真实跨度。

再取出下界, 也就是每个变量最小能到哪。

把 0 到 1 的归一化决策变量拉伸成真实工程尺寸 `x`。

把真实尺寸交给问题对象评估。此时算法已经不用直接碰上下界了。

本次真正做了多少次评估, FE 就加多少。

第二步: 真实尺寸被送进 APDL 和 ANSYS

1
`Ship_Panel_Problem.generate_mac()`

把 `h_web_L1`、`b_bot_R` 这类尺寸拼成 APDL 宏脚本。你可以把它理解成“给 ANSYS 写施工说明书”。

2
`run_ansys_eval()`

创建工作目录、写 `.mac`、找到 `MAPDL.exe`、启动批处理求解, 然后读取结果文本。

3
约束和目标回到优化器

目标值用 FEA 质量, 约束则来自最大弯曲应力、最大剪切应力和几何顺序约束。

X
Real x

第三步: ANSYS 回来的东西会被整理成优化能懂的格式

CODE 
con(1) = max_bend - task.bend_allow;
con(2) = max_shear - task.shear_allow;

h_web_L1 = x(1);
h_web_L2 = x(5);

PLAIN ENGLISH

第一条约束问的是: 最大弯曲应力有没有超过任务允许值。

第二条约束问的是: 最大剪切应力有没有超标。

接下来开始看几何关系, 先取中心纵骨高度。

再取侧纵骨高度。

如果 `h_web_L2 - h_web_L1` 是正的, 说明侧纵骨反而比中心纵骨还高, 这条几何约束就被破坏了。

!
当 ANSYS 出错时, 优化不会立刻崩

代码会给这个候选解一个巨大的惩罚值, 让算法自然把它淘汰掉。这是很常见的“让搜索继续往前走”的工程手法。

05

结果文件里到底有什么

跑完实验以后, 你最容易误解的地方就在这: `interleave_*.mat` 不是 GUI 里的 `MTOData.mat`。它是 `cmd_interleave` 自己打包出来的一套轻量结果格式。

脚本最后保存了哪些字段

CODE 
save_name = sprintf('interleave_%s.mat', datestr(now, 'yyyymmdd_HHMMSS'));
save(save_name, 'BestObj', 'BestCV', 'BestDecNorm', 'BestDecReal', ...
    'ConvergeObj', 'ConvergeFE', 'algo_names', 'active_tasks', ...
    'Reps', 'maxFE', 'Disable_Swap', 'Global_Seed', 'rep_seeds', ...
    'PopulationSizeStats');
PLAIN ENGLISH

文件名会自动带上时间戳, 所以每次运行默认都是一个新文件。

这里真正写入磁盘的是一组普通变量, 不是一个叫 `MTOData` 的总结构体。

`BestObj`、`BestCV`、`BestDecNorm`、`BestDecReal` 是最好结果视角。

`ConvergeObj` 和 `ConvergeFE` 是画收敛曲线用的轨迹。

后面这几个是实验元信息: 算法名、任务、重复次数、预算和 Swap 配置。

这份工作区现在还额外保存了 `Global_Seed`、每次 rep 的实际 `rep_seeds`、以及逐代 `PopulationSizeStats`。

读这个文件时, 你最关心的通常是这 6 类东西

O

BestObj

每个算法、每次 rep、每个任务的最终最佳目标值。

C

ConvergeObj

收敛曲线主体。画对比图时最常用。

D

BestDecReal

最终最优个体的真实尺寸, 不再是 0 到 1 的归一化值。

F

ConvergeFE

每个收敛点对应的真实 FE 位置, 不是简单的代编号。

S

Global_Seed / rep_seeds

告诉你这次实验随机性从哪里来, 以后怎么复现。

P

PopulationSizeStats

记录每代各任务的种群大小。现在你终于可以回答“这一代到底有多少个体”。

收敛曲线为什么不是原始每一代原样保存

CODE 
Result = Result_Gen(:, 1:maxGen);
for k = 1:size(Result_Gen, 1)
    Gap = FE_Gen(end) ./ (maxGen);
    idx = 1;
    i = 1;
    while i <= length(FE_Gen)
PLAIN ENGLISH

先预留出一个固定长度的新结果容器。

逐个任务或逐条轨迹处理。

用总 FE 除以 `maxGen` 算出采样间隔。

准备好往第几个采样点写数据。

再从原始 FE 序列头开始扫一遍。

这说明保存到 `.mat` 里的收敛历史, 是重采样后的版本, 不是未经压缩的全代历史。

!
两个很容易踩的坑

第一, GUI 的载入按钮默认执行 `load(..., 'MTOData')`, 所以 `interleave_*.mat` 不能直接当 `MTOData.mat` 用。第二, `.mat` 是二进制文件, 如果被文本工具碰坏, 你会看到“文件还在, 但里面像没东西”。

06

Runtime Start

这一节不再按“代码逐行翻译”的方式讲, 而是直接跟着 MATLAB 的真实运行轨迹走: 先启动会话, 再把问题对象搭起来, 然后把后续循环需要的结果容器一次性铺好。

Trace 1: 运行一开始, MATLAB 先清场再定位脚本目录

i
这里看的不是“语法”, 而是“启动顺序”

主脚本刚被执行时, 先发生的是环境整理和路径准备. 这一步不会产生优化结果, 但它决定了后面类文件、问题文件和辅助函数能不能被 MATLAB 找到.

1

Current line

cmd_interleave.m:L4-L6

What happens here

clear; clc; close all; 先把旧状态清掉; cd(fileparts(mfilename('fullpath'))) 把当前工作目录切到脚本所在位置; addpath(genpath(pwd)) 再把仓库里的子目录全部放进搜索路径.

Next jump

不跳文件, 继续留在 cmd_interleave.m 里往下执行.

Return point

直接推进到 cmd_interleave.m:L8 的配置区.

2

Current line

cmd_interleave.m:L8-L21

What happens here

这里不是算法在跑, 而是在写运行参数: 哪些任务要启用、重复几次、总 FE 上限是多少、收敛曲线要记录多少点, 以及早停和画图范围的阈值都先固定下来.

Next jump

仍然不离开 cmd_interleave.m; 这些值只是给后面的对象初始化和循环控制提供输入.

Return point

继续到 cmd_interleave.m:L24 的问题对象创建段.

Trace 2: 问题对象先出现, `setTasks()` 才是真正的跨文件入口

3

Current line

cmd_interleave.m:L24-L29

What happens here

prob = Ship_Panel_MTSO() 先把船板优化问题对象造出来; 接着把 N, maxFE, Cleanup 和 ActiveTasks 写进去; 最后在 prob.setTasks() 这一步让问题对象根据当前任务组合重新装配边界、维度和目标函数句柄.

Next jump

prob.setTasks() -> Ship_Panel_MTSO.setTasks.

Return point

返回 cmd_interleave.m:L31, 也就是继续构造算法对象的地方.

i
为什么这一步必须单独点出来

Ship_Panel_MTSO.setTasks 会在内部把 active task 映射成真正的设计空间, 组装 T, D, Lb, Ub 和 Fnc. 这意味着主脚本不是“猜”任务信息, 而是把控制权交给问题类去完成初始化, 然后再回到 cmd_interleave.m 继续执行。

Trace 3: 结果容器先占位, 后面的循环才有地方写数据

i
MATLAB 里的三个“第一次出现”

这几个构造不是算法本身, 而是运行时的存储骨架. 你可以把它们看成“先把抽屉摆好, 后面每次 rep / 每个任务 / 每条曲线只负责往里放东西”.

cell

First appearance

cell(nAlgo, 1) / cell(nTask, 1)

MATLAB meaning

cell(...) 创建的是 cell 容器, 里面每个格子都可以装不同大小、不同类型的内容. 这里用它装每个算法自己的结果表, 因为每个算法的收敛历史长度和嵌套层级都不一样.

Why it fits the trace

这让主脚本可以先完成“架子”初始化, 等算法真正跑完再按算法索引把数据填进去.

nan

First appearance

nan(nAlgo, Reps, nTask)

MATLAB meaning

nan(...) 先用 NaN 占住数值数组的位置. 这比全零更适合结果预分配, 因为未写入的位置一眼就能看出来, 后面统计时也不会把“没结果”误认成真实的 0.

Why it fits the trace

在 runtime 里, 这相当于先留白, 再让每次 rep 的最终最佳值逐格落位.

g

First appearance

gobjects(1, nTask) / gobjects(nAlgo, nTask)

MATLAB meaning

gobjects(...) 预先创建图形句柄数组. 这些位置以后会装进 subplot、animatedline 之类的对象, 所以先给它们一个“句柄型”的空壳最合适.

Why it fits the trace

这不是在画图, 而是在为后面的实时曲线更新准备控制点. 当你进入下一模块时, 它们就会立刻被拿去连接每个任务子图.

i
这一步结束后, 脚本才真正准备好进入循环

到这里为止, 主脚本已经完成启动、问题装配和结果占位. 下一模块才会接着讲图窗句柄如何建立、以及 algo.run(prob) 触发的主循环轨迹。

What fails

这一段只处理真正的前置失败: fopen(mac_file, 'w') 打不开宏文件, 或者 find_ansys_exe() 找不到可执行文件。

Penalty behavior
