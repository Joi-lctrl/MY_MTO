谁在参与这场实验

理解 `cmd_interleave` 的捷径, 不是背完整个仓库, 而是先认清“演员表”。你只要知道谁负责调度、谁负责出题、谁负责求解、谁负责工程仿真, 后面很多代码就会突然变好懂。

先认识 5 个核心角色

C

cmd_interleave

导演。它安排任务、算法、预算、随机种子和结果保存。

P

Ship_Panel_MTSO

翻译官。它把“任务编号”翻成上下界、维度和真正可调用的评估函数。

B

Algorithm 基类

公共骨架。记 FE、记每代结果、统一 `getResult()` 输出格式。

G

GA / CEDA-DW

真正提出候选设计的人。一个简单直接, 一个会利用跨任务迁移。

A

APDL + ANSYS

裁判。它不关心算法名气, 只认结构质量和应力约束。

问题对象是怎么把任务准备好的

CODE 
ship_prob = Ship_Panel_Problem();
active_tasks = Prob.ActiveTasks(:)';

for k = 1:numel(active_tasks)
    task_id = active_tasks(k);
    [lb{k}, ~, ub{k}] = ship_prob.get_design_space(task_id);
    fnc{k} = Prob.makeTaskFcn(task_id);
end
PLAIN ENGLISH

先拿到最底层的 ship panel 任务表, 它知道每个任务的真实工程参数。

把当前想跑的任务列表取出来, 这里通常就是脚本设进去的 `[3 5]` 这种数组。

逐个任务处理, 不偷懒也不假设所有任务都一样。

给这个任务取出上下界。也就是告诉算法: 哪些尺寸能动, 最小多小, 最大多大。

再给这个任务造一个专属评估函数。之后算法只需要调这个函数, 不用理解 ANSYS 细节。

i
一个很有用的软件工程模式

这里做的是 封装。算法只看见“任务函数”, 不直接碰 APDL 宏、结果文件和 ANSYS 路径。
