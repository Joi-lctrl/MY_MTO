03

一次 rep 是怎么推进的

`rep` 可以理解成“同一实验再独立重来一次”。它的存在不是为了热闹, 而是为了防止你被一次好运气或坏运气骗到。

一轮 rep 的骨架非常朴素

1
先固定随机种子

这样这次 rep 的随机数来源就被钉住了, 两个算法可以共享同一把“骰子”。

2
重新设置问题对象

脚本会再次调用 `prob.setTasks()`。这能保证任务边界和函数句柄是干净的一套。

3
给算法塞配置

`Result_Num` 决定收敛历史最终保留多少点, `Save_Dec` 决定是否把决策变量也存下来。

4
算法开始代际循环

GA 和 CEDA-DW 都会一代一代提出候选解, 评估后再筛一轮, 直到 FE 用完或早停触发。

脚本在每次开跑前做了什么

CODE 
rng(seeds(rep));
prob.setTasks();
algo = algos{a};
algo.Result_Num = Results_Num;
algo.Save_Dec = false;
if Disable_Swap && isprop(algo, 'Swap')
    algo.Swap = 1;
end
algo.reset();
PLAIN ENGLISH

先把这次 rep 的随机源锁到固定种子上。

把问题对象重新整理一遍, 避免上一个算法留下的状态影响这一个。

取出当前要跑的算法对象。

告诉算法: 收敛结果最后只留 `Results_Num` 个采样点。

这里明确不保存每代 `Dec`, 所以默认只保留目标值轨迹和最终最优解。

如果算法带 `Swap` 属性, 这里统一把它关成脚本想要的模式。

最后重置算法内部状态, 让它像刚开机一样开始这一轮。

Global_Seed = 2604 全局起点种子, 用来生成每个 rep 的实际种子
rep_seeds = (0:Reps-1) + Global_Seed 每次重复实验真正喂给 `rng()` 的数字
Result_Num = 50 收敛历史不会原样保存全部代数, 最后会重采样成 50 个点

算法基类每一代都会顺手记账

CODE 
flag = Algo.FE < Prob.maxFE;

isSingleObj = max(Prob.M) == 1;
for t = 1:Prob.T

PLAIN ENGLISH

先判断 FE 预算是否还没花完。没花完才能继续下一代。

取出当前代编号 `gen`。

这条 ship panel 链路是单目标问题, 所以这里会走 `isSingleObj` 分支。

按任务一个个记录当前代结果。

单目标时不保存整个人口, 只记住“这一代当前最优个体”。

第一件被记下来的就是最优目标值 `Obj`。

i
为什么这点很关键

很多人以为 `.mat` 里一定保存了每代每个个体。对这条单目标链路不是这样。默认保存的是“每代最好那一个”的历史, 不是完整人群快照。
