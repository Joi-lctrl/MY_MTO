What happens here

extra = struct(...) 先创建一个固定字段的诊断包: error、feasible、质量、最大应力和几何差值都先占位。后面就算某一步失败, 调用者也还能拿到结构化状态。

Return point

如果前面的准备都成功, 控制权继续流向宏文件生成和 ANSYS 启动阶段; 如果还没出错, 这里不会 return。

i
为什么要用 struct(...)

这不是随手拼一个杂物袋, 而是把每次评估要汇报的状态字段一次性定死。调用者后面只要看 extra.error、extra.feasible 和各个测量值, 就知道这次评估是成功、失败, 还是只拿到了部分诊断数据。

Trace 2: 三个早退点都走同一套惩罚路线

2

Failure path

run_ansys_eval.m:L57-L77

What fails

这一段只处理真正的前置失败: fopen(mac_file, 'w') 打不开宏文件, 或者 find_ansys_exe() 找不到可执行文件。

Penalty behavior

这两个前置失败都会先发 warning(...), 然后把 obj 设成 1e10, con 设成 [100 100 100 100], 再把 extra.error = true, 最后直接 return。

Why this matters

这一步的作用是把“连输入文件都没准备好”这种问题尽早拦住, 不让后面的 ANSYS 运行阶段接着浪费时间。

3

Failure path

run_ansys_eval.m:L79-L102

What fails

这一段只管 ANSYS 真正跑起来之后的失败: system(cmd) 返回非零状态, 或者结果文件存在但 parse_results 读不出有效数值。

Penalty behavior

两个后置失败都会沿用同样的惩罚输出, 这样调用方不用区分是哪一步崩了, 只要知道这次评估不可用即可。

Return point

失败后直接退回 Ship_Panel_MTSO.evalTaskBatch, 由上一层决定是否把这次错误再显式重罚一次。

L113-L115 约束向量先清零, 再填入弯曲和剪切的超限量; 这里的正值就是违反, 负值或零就是满足。

!
错误到惩罚的路径是双层防线

run_ansys_eval 自己会在失败时返回惩罚值; 进入 Ship_Panel_MTSO.evalTaskBatch 之后, 还会再看 extra.error, 把这次解显式记成高惩罚, 保证优化器看到的始终是稳定的数值输出, 而不是中断。

Trace 4: 回到批量评估器, 这里把错误翻译成最终记录值

What happens here

如果 extra.error 为 true, 这一层会把目标值重写成 1e10, 把四条约束写成一整行大正违反, 然后继续打印调试信息。这样做的目的不是“报错退出”, 而是让优化器把坏解自然排到后面。

Return point
